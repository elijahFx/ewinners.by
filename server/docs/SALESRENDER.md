# SalesRender → E-Winners

Списание с баланса клиента идёт по двум статусам заказа:

| Статус SalesRender | id | Что списываем |
|---|---|---|
| **Принят** | 2 | базовый тариф за обзвон — 3 BYN, либо 5 BYN с апсейлом/кроссейлом |
| **Вручено** | 5 | доплата за выкуп **+1,50 BYN** — только если у клиента включён «Отдел выкупа» |

Остальные статусы (Обработка, В пути, Ждет вручения, Отмена и т.д.) не списывают
ничего. В SalesRender **ничего не меняем** — только принимаем webhook.

## Тарифы

| Когда | Условие | Услуга (code) | Сумма по умолчанию |
|---|---|---|---|
| Принят | нет галочек `krossejl` и `apseil` | `sr_order_base` | **3 BYN** |
| Принят | хотя бы одна галочка (или обе) | `sr_order_upsell` | **5 BYN** |
| Вручено | у клиента включён «Отдел выкупа» | `sr_order_delivered` | **+1,50 BYN** |

Цены берутся из **прайса проекта** (Проекты → Тарифы). Доплата `sr_order_delivered`
списывается, если в карточке клиента включена галочка **«Отдел выкупа»** и в прайсе
проекта задана цена этой услуги.

Идемпотентность: базовое списание — `sr-accepted-{orderId}`, доплата —
`sr-delivered-bonus-{orderId}`. Повторный вебхук по тому же заказу не спишет дважды.
Для заказов, списанных до перехода на статус «Принят», учитывается и старый ключ
`sr-delivered-{orderId}` — чтобы не списать повторно.

## Env

```env
SALESRENDER_API_KEY=...          # общий секрет для webhook (заголовок X-Api-Key либо ?api_key=)
SALESRENDER_COMPANY_ID=123       # запасной вариант (внутренний id), если ID не пришёл
```

## Endpoint

```
POST /api/crm/salesrender/delivered
Header: X-Api-Key: <SALESRENDER_API_KEY>
Content-Type: application/json
```

Пример тела:

```json
{
  "orderId": "3324",
  "statusId": 5,
  "statusName": "Вручено",
  "krossejl": false,
  "apseil": true,
  "projectId": 87,
  "project": { "id": 87, "name": "ID 87 - ИП Рудак" },
  "employeeName": "Оператор"
}
```

**Важно:** в SalesRender клиенты заведены как **Проекты** (ID 87 — ИП Рудак,
86 — ИП Сенина и т.д.), поэтому вебхук должен передавать **ID проекта SalesRender**.
Он хранится у клиента E-Winners в поле `companies.salesrender_id`.

**Как выбирается клиент для списания (по приоритету):**

1. **ID проекта SalesRender** — из полей `projectId` / `project_id` /
   `project.id` / `salesrenderProjectId` / `salesrenderId`. Ищем по
   `companies.salesrender_id`. Это основной способ: ID важнее названия.
   Если ID передан, но такого клиента нет → `404` (название в этом случае
   **не** используется, чтобы не списать с чужого клиента).
2. `companyApiKey` — по CRM-ключу компании
3. `companyId` / `company_id` — сначала как ID проекта SalesRender, затем как
   внутренний id E-Winners (совместимость со старыми настройками)
4. `SALESRENDER_COMPANY_ID` из `.env`
5. `companyName` / `organization` / `company.name` — поиск по названию
   (без учёта регистра, кавычек, префиксов ООО/ИП). Только как запасной вариант
   для клиентов без ID проекта; в лог пишется предупреждение.

Если клиент не найден → `404`. Если по названию нашлось несколько → `409`.

**Как выбирается проект E-Winners (для прайса):**

Поле `projectId` понимается двояко: сначала пробуем как ID проекта SalesRender
клиента, и только если не совпало — как внутренний проект E-Winners.

- указан внутренний проект E-Winners → списываем по его прайсу;
- не указан, а у клиента **один** проект → берём его автоматически;
- не указан, а проектов **несколько** → подбираем тот, в чьём прайсе есть нужная
  услуга. Баланс у клиента один, поэтому проект влияет только на цену.

Списание всегда идёт с **единого баланса клиента** (`companies.balance`) —
независимо от того, сколько у него проектов и по какому из них пришёл заказ.

### Где взять ID проекта

**SalesRender → Проекты → колонка ID** (например, `87`). В E-Winners он
указывается в карточке клиента, раздел **Клиенты** → поле
«ID проекта в SalesRender» (его можно поправить прямо в таблице клиентов)
и хранится в `companies.salesrender_id` (уникальное).

Идемпотентность: повтор по тому же `orderId` не спишет дважды (`sr-delivered-{orderId}`).

## Триггер в SalesRender (настроить вручную)

1. **Управление → Триггеры → +**
2. Событие: **Обновлён** (ORDER_UPDATED)
3. Фильтр: **статус заказа == Вручено** (id 5).
   Фильтр `TRUE` тоже работает (лишние события отсекаются на нашей стороне),
   но тогда на каждый апдейт заказа пишется запись в `crm_event_log`.
4. Действие: **Отправить вебхук**
   - **URL целиком, вместе с путём:**
     `https://<ваш-api>/api/crm/salesrender/delivered`
     (без `/api/crm/...` будет `404 Cannot POST /`)
   - **Авторизация:** у действия «вебхук» в SalesRender есть только поля
     `uri`, `contentType` и `query` — **заголовки задать нельзя**.
     Поэтому ключ передаётся в URL:
     `.../api/crm/salesrender/delivered?api_key=<SALESRENDER_API_KEY>`
   - **Content-Type:** `JSON`

### Тело вебхука (GraphQL-вид)

Проверенный набор полей для триггера:

```graphql
{
  id
  project { id }
  status { id name }
  data {
    booleanFields { field { id name } value }
    stringFields { field { id name } value }
  }
}
```

`project.id` — это ID проекта SalesRender, он же клиент в E-Winners.

**Важно про `field { name }`:** без `name` приходит только `id` поля, и
сопоставить галочку с услугой невозможно — нужен именно **слаг** (`name`).

**Про апсейл и кроссейл.** В CRM E-Winners это булевы поля:

| Слаг | Название | Тип | Статус |
|---|---|---|---|
| `krossejl` | Кроссейл | Boolean | активное |
| `apseil` | Апсейл | Boolean | активное |
| `apsejl` | Апсейл | String | **архив** (устаревший дубль) |

Так как оба — `Boolean`, они приходят в **`booleanFields`**, а не в
`stringFields`. Если в запросе нет `booleanFields` — любой заказ спишется как
`sr_order_base` (3 BYN), и цена 5 BYN не применится никогда.

Дополнительно можно передать `employeeName` — попадёт в операцию.

## Что мы НЕ читаем

- `data.id` — это id заказа, он используется только для идемпотентности.
- `cart`, `logistic`, `data.*Fields` — принимаются, но на списание не влияют.

## Важно про доступы

Логин/пароль личного кабинета SalesRender **не нужны** серверу E-Winners.  
Достаточно `SALESRENDER_API_KEY` + webhook.
